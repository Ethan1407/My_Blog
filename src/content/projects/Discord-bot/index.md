## 一、 開發動機：父親的啟發與平台選擇

製作這個 Discord 機器人的契機，源自於爸爸對未來科技趨勢的洞察。他提醒我 AI 將是未來的核心，並鼓勵我開發能自動處理資料的工具。初期討論時，我們曾考慮過 Line 或 Discord，但考量到開發的彈性與門檻，我最終選擇了 Discord 作為起點。當時我對 VSCode 尚不熟悉，因此透過觀看教學影片，從最基礎的「伺服器訊息監聽」學起。透過實作機器人回報訊息修改與刪除的功能，我對 Discord Bot 的運作機制有了初步且紮實的掌握。

## 二、 核心功能：自動化語音轉心得流程

掌握基礎後，我開始動手實踐與爸爸討論的「自動化工作流程」，我們的目標是：上傳錄音檔後，由機器人自動產出逐字稿後，再透過AI製作心得草稿等資料。我先連接了具備 API 呼叫功能的語音轉文字軟體，成功實現錄音檔到逐字稿的轉換。接著，我進一步連接對話式 AI，並結合預先設定好的提示詞。雖然過程中一度遇到 AI 無法回應的API問題，但在與 Gemini 協作除錯後順利解決。現在，只要上傳錄音，機器人就能自動重整出一份活動心得，讓我們只需進行細部修改，大大省去了從零開始構思的時間。

## 三、 功能擴充：晨報系統與智能待辦清單

除了處理錄音檔，我還為機器人加入了溫暖的「晨報」功能。透過串接天氣預報網站的 API，機器人每天早上都會定時推送今日天氣。此外，我還設計了待辦事項（To-do List）系統，並將其與錄音處理功能連動。每當機器人接收並處理完一份錄音後，它會自動在待辦清單中新增「處理錄音檔」與「製作簡報」的提醒事項，確保後續的工作進度不會被遺漏，實現了功能間的邏輯串聯。

## 四、 雲端部署：實現 24 小時不間斷服務

為了讓機器人能隨時隨地待命，我學習了如何將程式發佈到雲端平台 Railway。在部署之前，機器人必須依賴我個人電腦的啟動才能運作；部署完成後，機器人便能 24 小時不間斷地監聽伺服器訊息並執行任務。這不僅提升了工具的實用性，也讓我對後端服務的發佈流程有了實戰經驗。

## 五、 結語：實作是通往技術成長的捷徑

這次 Discord 機器人的開發，是我技術成長的重要轉折點。透過這個專案，我從原本對 VSCode 感到陌生，到現在能熟練地管理程式碼，並對 GitHub 的操作有了更深層的理解。這份經驗也直接啟發了我後續製作「桌寵」與「個人網頁」的靈感。我相信，實作才是進步最快的方法，這場從無到有的開發經驗，正是最好的證明。
